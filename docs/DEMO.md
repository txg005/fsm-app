# FSM: демонстрация за 5–10 минут

Сценарий защиты, **не отчёт о выполнении**. Показываем CRUD локального inspection_results, offline Room, фото/GPS, durable Outbox и полезный Service ↔ UI. Полный статус/evidence и непройденная матрица — [ACCEPTANCE.md](ACCEPTANCE.md). Время ориентировочное: сеть, GPS и retry backoff могут увеличить ожидание; не обходить очередь ради соблюдения тайминга.

## До начала (не входит в 5–10 минут)

- Запущен настроенный backend; health `http://127.0.0.1:8080/health` возвращает `ok`. Инструкции: [backend README](../backend/README.md), [Android README](../android/README.md), [Windows/Studio](BUILD-WINDOWS.md). Учётные данные вводить приватно, не показывать `.env`, токены и реальные фото/координаты в записи экрана.
- Совместимый APK уже установлен; package/version и сертификат проверены. **CI debug APK не обещает upgrade** APK из другой среды. Не uninstall/clear data для обхода подписи: это удаляет локальную работу. Для следующих локальных сборок сохранять стабильный приватный debug keystore того же окружения, не публикуя его/пароли/keys.
- Заранее войти онлайн, обновить список и выбрать **доступную ASSIGNED-заявку без незавершённой чужой демонстрации**. На свежем seed было по2 заявки на инженера, но seed insert-once: рестарт не возвращает CLOSED в ASSIGNED и не добавляет задания существующему инженеру.
- **В пользовательской базе все заявки engineer1 уже закрыты; engineer2 тоже закрыл как минимум одну. Свободная заявка не гарантирована.** Если ASSIGNED нет — остановить сценарий до закрытия: показать готовый CLOSED read-only, а для полного repeat demo заранее согласовать с оператором безопасную новую тестовую заявку/изолированную демонстрационную среду без изменения существующих данных. Create-work-order endpoint/UI в v1 нет; эта инструкция не выдумывает API/SQL для создания или reopening. Подготовка новой заявки — явное внешнее предусловие, не выполненная функция приложения.
- Использовать синтетический комментарий/тестовое фото; подготовить способы выключить сеть и повернуть экран. Сеть эмулятора проверить фактически: одна иконка airplane не доказывает недоступность host API.

## Показ (5–10 минут после подготовки)

| Время | Действие | Проверка / что объяснить |
| --- | --- | --- |
| 0–1 мин | Список → карточка ASSIGNED → «Начать осмотр» | Видно различие «Заявка: Назначена» и «Черновик на устройстве». Это create/read результата, не создание заявки. |
| 1–2 мин | Заполнить чек-лист, допустимое показание (для seeded pressure, например2.5bar в диапазоне0–10), тестовый комментарий; дождаться окончания «Сохранение…», открыть снова и изменить | Update сохраняется локально. Неподтверждённые последние нажатия при аварии не обещаются. |
| 2–3 мин | Из карточки удалить **этот тестовый DRAFT** с подтверждением, проверить отсутствие результата; снова начать и заполнить | Delete не удаляет серверную заявку. Сделать это до close: QUEUED/CLOSED редактировать и удалять нельзя. Не удалять ранее подготовленную чужую работу. |
| 3–4 мин | Выключить сеть; прочитать draft; повернуть portrait ↔ landscape с клавиатурой, вернуться в карточку | Сохранённые поля видны, управляющие элементы достижимы прокруткой. CI Stage3 проверил ограниченный landscape/IME на одном API36-эмуляторе; этот ручной прогон и другие устройства фиксировать отдельно. |
| 4–5 мин | «Фото и закрытие»: добавить одно тестовое фото, проверить local preview. Закрыть кнопкой «Сохранить закрытие и поставить в очередь» | Фото optional; GPS запрашивается автоматически до15с. Разрешить для fresh fix либо отказать для честного MISSING: без координат закрытие допустимо. Не обещать GPS indoors/в airplane. |
| 5–6 мин | Открыть «Очередь и технические логи»; при сети off остановить/повторить передачу, затем завершить процесс через настройки Android и открыть снова, не очищая данные | Local QUEUED и фото сохранены, не server CLOSED. При одном фото ожидаются upload + close операции с UUID. После force-stop не обещается фоновая работа; приложение открыть явно. Не применять «Очистить данные». |
| 6–8 мин | Вернуть связь, из видимого приложения нажать «Отправить сохранённые работы»/«Запустить передачу». Показать уведомление Service, Home → возврат и статусы | Реальная полезная работа Service: фото прежде close, состояние через Room/Flow. Счётчики — операции, не проценты/ETA. Если передача успела закончиться, не выдавать cancel-тест за выполненный. |
| 8–10 мин | После ACK показать карточку/«Фото и результат закрытия», техническую очередь; повторить sync | Upload ACK сам по себе не закрывает заявку. Успех: результат подтверждён сервером, CLOSED, upload/close ACKED для этой заявки, фото осталось локально. Перед повтором записать показанную версию; после обновления списка она не растёт повторно, статус остаётся подтверждённым. |

Если хотите показать именно отмену активной передачи, используйте уведомление «Остановить» или технический экран «Остановить передачу», **пока операция ещё выполняется**. Остановка не отменяет локальный close и не доказывает, что сервер ничего не принял. Повторить прежнюю очередь, не создавать новый close/key при unknown outcome. Слишком короткую передачу честно отметить «cancel не удалось наблюдать», не добавлять задержки в runtime ради показа.

## Если что-то пошло не так

- Нет сети/подтверждения: сохранить QUEUED/RETRY_WAIT, вернуть связь и повторить ту же операцию. Не считать отсутствие ответа отсутствием server commit.
- AUTH_REQUIRED: войти тем же пользователем; локальную БД/фото не удалять.
- Окончательный FAILED или конфликт: показать сравнение версий; действия получают fresh authorized GET. При ошибке GET локальная работа остаётся; сервер CLOSED не возвращается в DRAFT. Новый close допустим только после явного разрешённого возврата к DRAFT, не для обхода неизвестного исхода.
- Нет свежего GPS: показать причину отсутствия, не подставлять нули/старую точку. Не логировать и не публиковать точные координаты.
